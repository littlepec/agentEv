## C4 — HTTP3

**Question (verbatim):** "Explain HTTP/3 and QUIC and their key improvements over HTTP/2."

**KEY CLAIM (KC):** HTTP/3 runs over QUIC (a UDP-based transport, RFC 9000; HTTP/3 is RFC 9114), which avoids TCP head-of-line blocking, has built-in TLS 1.3 encryption, and enables faster (often 0-RTT) connection setup versus HTTP/2 over TCP.

**Source excerpts:**
1. "This document describes a mapping of HTTP semantics over QUIC." — IETF, RFC 9114 "HTTP/3", June 2022, https://www.rfc-editor.org/rfc/rfc9114.html (IETF Trust; RFC 9114).
2. "a lost or reordered packet causes all active transactions to experience a stall regardless of whether that transaction was directly impacted by the lost packet" — RFC 9114 (describing HTTP/2-over-TCP head-of-line blocking), same URL.
3. "QUIC also incorporates TLS 1.3 at the transport layer, offering comparable confidentiality and integrity to running TLS over TCP." — RFC 9114, same URL.
4. "QUIC, a transport layer network protocol which uses user space congestion control over the User Datagram Protocol (UDP)." — Wikipedia, "HTTP/3", https://en.wikipedia.org/wiki/HTTP/3 (CC BY-SA 4.0; accessed 2026-09-14).
5. "On 6 June 2022, IETF published HTTP/3 as a Proposed Standard in RFC 9114." — Wikipedia, "HTTP/3", same URL (CC BY-SA 4.0).
6. "Because QUIC provides native multiplexing, lost packets only impact the streams where data has been lost." — Wikipedia, "HTTP/3", same URL (CC BY-SA 4.0).

**KC truth check:** TRUE.
- HTTP/3 = RFC 9114, maps HTTP over QUIC: excerpts 1, 5.
- QUIC is UDP-based, defined in RFC 9000 (QUIC transport, published May 2021): excerpt 4; RFC number confirmed via https://www.rfc-editor.org/info/rfc9000/ (RFC 9000, "QUIC: A UDP-Based Multiplexed and Secure Transport", May 2021).
- Avoids TCP head-of-line blocking: excerpts 2 (the HTTP/2 problem) and 6 (QUIC's fix).
- Built-in TLS 1.3: excerpt 3.
- Faster / 0-RTT setup: QUIC combines transport and cryptographic handshake; 0-RTT is supported for resumed connections (governed by RFC 9001, "Using TLS to Secure QUIC"). See "unverified" note — the explicit "0-RTT" phrasing came from search summaries, not a directly fetched verbatim RFC quote. Nuance: 0-RTT applies to session resumption (not the very first connection) and carries a known replay-attack caveat.

**truth basis:** independently-verifiable-fact (standards RFCs).

**sufficient to answer? yes** — protocol identities, transport, HOL-blocking difference, TLS 1.3, and the latency/0-RTT improvement are sourced; only the 0-RTT phrasing needs a direct RFC 9001 quote before final publication.
