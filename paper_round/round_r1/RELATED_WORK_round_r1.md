# 相关工作定向核对（round_R1c，2026-09-15）

问题：主源含 OCR 级噪声、投毒的次要材料干净时，模型把干净次源当噪声主源的"解码器"并采纳其数字——这是否已有记录。由只读子 agent 经 WebSearch/WebFetch 读 arXiv abs/html 摘录（引文 <25 词，附节号；未开 PDF；主会话未本地二次核对，标"子 agent 摘录"）。

## 1. OCR／抽取噪声对 RAG 与问答的影响

| 工作 | 噪声类型 | 结果（子 agent 摘录） | 与本轮的关系 |
|---|---|---|---|
| OHRBench "OCR Hinders RAG"（2412.02592，ICCV 2025） | 语义噪声（真实 OCR 误识别，轻／中／重）与格式噪声（标记、空白） | 语义噪声加重"nearly a 50% performance decline"（§4.3.1）；格式噪声主要影响多模态题，最大损失 12.7%／9.1%；表格／公式类证据最难 | 与本轮"排版噪声无害、字符级噪声有害"的分界最接近；但单来源、只测准确率，不测来源切换 |
| MultiOCR-QA（2502.16781，CIKM 2025） | 插入／删除／替换，三档 | 替换错误影响最重（§5.3）；答案含数字日期但无按类型拆分 | 无第二来源、无"从上下文修复"分析 |
| InduOCRBench "When Good OCR Is Not Enough"（2605.00911，2026） | 多栏、跨页表、阅读顺序、水印 | 结构与语义错误在 CER 低时仍致检索失败；§3.4 报告 LLM 补偿：RAG 准确率高出 OCR 准确率 6–11 点，但"非标准阅读顺序破坏逻辑连贯"时补偿失效 | 证明生成器会用上下文修复字符级损伤；未问"用了什么上下文"、错误第二来源能否劫持修复 |
| NoiserBench（2408.13533） | 七类含正字法噪声与反事实噪声 | 正字法噪声只损 ~2.6 点，反事实噪声损 41–52 点（Table 1）；噪声以**单独文档**加入，金文档从不被破坏 | 恰好缺"噪声主源＋干净反事实"这一格 |
| 后 OCR 纠错（CLOCR-C 2408.17428；"No Free Lunches" 2502.01205） | — | LLM 能据上下文修复 OCR 文本，也会过度纠正；误导性提示降低性能 | 这就是"用上下文解码"的机制，但作为纠错任务研究，非对抗 |

五者均未测"所有多位数字被拆开"这类噪声。

## 2. 来源冲突且一方退化

| 工作 | 发现（子 agent 摘录） | 关系 |
|---|---|---|
| "What Evidence Do LMs Find Convincing?"（2402.11782，ACL 2024） | 风格特征对胜率中性或负面，相关性特征显著提高胜率 | 未测噪声变体；噪声段落可能因关键词破碎而失去相关性，与本轮方向一致但未测 |
| "Adaptive Chameleon or Stubborn Sloth"（2305.13300，ICLR 2024） | 反记忆证据"coherent and convincing"时被接受 | 连贯性是最接近"流畅偏好"的已记录线索；无噪声操作 |
| "Blinded by Generated Contexts"（2401.11911，ACL 2024） | 模型偏好生成上下文，因其与问题更相似且检索上下文被"分段破坏完整性" | 唯一一篇"输的一方是退化的、赢的一方干净且错"的工作；退化是截断不是 OCR |
| "Whose Facts Win?"（2601.03746）、"Rational Synthesizers or Heuristic Followers?"（2601.06189） | 机构归属、重复、改写频率、位置驱动偏好 | 不操作文本质量 |
| Credibility-aware generation（2404.06809）、DRAGged into Conflicts（2506.08500） | 可信度是指定的，不是从文本状态推出的 | 无噪声来源类别 |

**对抗式干净次源 vs 噪声主源：未找到。** NoiserBench 明确保持金文档干净；投毒攻击文献（PoisonedRAG 等）注意到投毒文本"well-formed"，但从未与被破坏的真源配对。

## 3. 数字在空格／分词扰动下的阅读

"Tokenization counts"（2402.14903）：分隔符改变数字分块与算术准确率，但分隔符是帮助；"The Text Uncanny Valley"（2605.07186）：词内插空格呈 U 形准确率，是否含数字未证实；字符级扰动鲁棒性（2510.14365）与数值敏感性（2511.08022）：对错字鲁棒但"对数值特征极其敏感"；Levy & Geva（2410.11781）：数字内部按十进制逐位表示，"8 8"更像两个数字而非 88——机制提示，非本案例结果。**没有论文专门评估从文档中恢复被拆开数字。**

## 4. 判定

1. 整体未见记录：没有工作把 OCR 噪声的真主源与干净的对抗性次源配对并测答案切换。
2. 已记录的部分：字符／语义级噪声比排版噪声伤害大得多；LLM 会用上下文修复噪声文本且会过度纠正；冲突时偏好连贯、相关、完整的文本。
3. 未记录：经干净笔记"解码"噪声数字的路径；数字拆分下的数值事实；对抗式干净次源。本轮观察是这三者的新组合——若 R1c 确认稳定，可写为"复现已知部分＋新组合"，不称全新现象。
4. 最公平的对照基准：NoiserBench 加"用其正字法噪声破坏金文档、反事实文档保持干净"；OHRBench 重语义噪声文本加干净干扰项是最接近真实 OCR 的替代。
5. 注意：2605.07186 与 2605.00911 的数字细节依据摘要，引用前需核原文。
