# 相关工作定向核对（round_S3，2026-09-15）

范围按用户指令限定；由两个只读子 agent 经 WebFetch 读取原文并摘录（引文 <25 词），主会话据此判定与本轮的关系。Fact2Fiction 的引文已在 2026-09-14 由主会话本地核对；其余条目的引文未在本地二次核对，标注为"子 agent 摘录"。不把任何未测项写成"已有方法失败"。

| 工作 | 与本轮相关的能力／前提（子 agent 摘录） | 对本轮的含义（主会话判定） |
|---|---|---|
| Contextual Retrieval（Anthropic 博客 2024-09） | 用 LLM 为每块生成 50–100 token 的情境说明后再嵌入与建 BM25 索引；top-20 失败率 5.7%→3.7%（仅情境嵌入）→2.9%（＋BM25 混合）→1.9%（＋重排）；一次性 $1.02/百万 token；**未主张跨块／跨节问题**；并建议 20 万 token 以下"直接把整个知识库放进提示" | 混合检索与情境化是无额外查询调用的结构修法；"小语料直接全文"与本项目 C-1 结论一致。本轮的"结构修复"取其无 LLM 的部分：章节感知切块＋余弦/BM25 并集；不做 LLM 情境生成 |
| IRCoT（Trivedi 等，ACL 2023，2212.10509） | 用上一步 CoT 句子作为下一次 BM25 查询，最多 8 步／15 段；相对单步检索召回提升 3.5–22.6 点；测试时不用金段落；每问约 2–9 次 LLM 调用（子 agent 推断） | "有限主动补查"的原型：本轮只做 1 次缺口检查＋≤2 条补查查询，属 IRCoT 思路的最小截断版，不冒充其方法 |
| Sufficient Context（Joren 等，ICLR 2025，2411.06037） | 定义"充分上下文"＝存在可由上下文支持的合理答案，多跳最多 4 跳；自动判定器 93% 准确；发现模型在上下文不足时倾向作答而非弃答；提出的干预是选择性弃答，**不提出补查** | 本项目 C-0 观察到宿主在空上下文时会弃答、在只有笔记时自信作答，与其"不足时仍作答"的发现一致；本轮的缺口检查借用其"充分性"定义，作为触发条件 |
| CRAG（Yan 等，2401.15884） | 轻量评估器给每篇文档打相关性分；只要有一篇高于上阈值即判"Correct"不再补查；"Incorrect"走网络搜索；无离线变体描述 | 对"需要两块、只取到一块"的情形，其规则会判 Correct 而不补查（主会话推断）；本轮不实现 CRAG |
| RobustRAG（Xiang 等，2405.15556 v2） | 隔离—聚合；前提：良性 top-(k−k′) 段落不变、"有用的良性段落多于恶意段落"；**未涉及正确段落未被取回的情形** | 保障不覆盖本轮的检索缺失型失效；不作为对照 |
| ReliabilityRAG（2509.23519） | 可靠性信号来自检索器排名或外部分数；NLI 矛盾图＋最大独立集；前提 k′≤k/5 且恶意文档与良性文档矛盾；保证的是排除恶意文档而非答案正确；不涉及检索缺失 | 同上；本轮单文档且正确段落常未入窗，不满足其前提 |
| Fact2Fiction（2508.06059） | 每条主张注入 m＝1–8% 的证据数（多文档），可事前查询受害系统；ASR＝裁决翻转 | 已在阶段 B 参照记录；本轮沿用单文档权限收紧迁移 |
| ADMIT（2510.13842） | 注入 1–5 条可读事实段落，正确证据同时在场，黑盒；ASR 只算翻转不算 NEI；测试了困惑度／ROUGE 过滤等，不含 RobustRAG 类 | 与本项目权限最接近的攻击近邻；本轮不改攻击 |
| ADORE（2606.13905） | 迭代查询扩展：LLM 改写→检索→LLM 打分→反馈；"覆盖饱和"指新文档数量，不是子问题覆盖；只做 IR 评测 | **不是**"覆盖驱动补查"；不据此实现任何东西 |
| FAIR-RAG（2510.22344）、S2G-RAG（2604.23783） | 把问题拆成所需发现清单／判断证据是否支持作答并输出缺口项，再生成针对性子查询（子 agent 检索所得） | "缺口驱动补查"已有发表方法；本轮的最小补查只作对照，明确标注为其思路的截断适配，不称新方法 |

## 对本轮设计的直接推论

1. 无 LLM 的结构修法（章节切块＋双通道并集）和"直接全文"都有现成依据；后者在小语料下被 Anthropic 明确推荐。
2. 有限主动补查的现成原型是 IRCoT／FAIR-RAG／S2G-RAG 一类；本轮实现为"一次充分性缺口检查→≤2 条补查→同一检索器再取"，是截断适配，结果只说明该截断版够不够。
3. 两类鲁棒 RAG 保障都以正确段落已在 top-k 为前提，本轮观察到的检索缺失在其保障范围之外，不能把它们写成"失败"。
